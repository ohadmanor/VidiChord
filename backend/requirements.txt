# VidiChord backend dependencies.
#
# Python 3.11 or 3.12 is recommended. Everything here except madmom installs
# cleanly on 3.13/3.14 as well, but madmom has no wheels and does not build
# from source beyond 3.12. Without it the app still runs:
# beat tracking falls back to librosa and chord fusion uses two engines
# instead of three. See README.md.

# --- web layer ---
fastapi>=0.110
uvicorn>=0.27
pydantic>=2.6

# --- audio acquisition ---
# yt-dlp goes stale faster than anything else here: YouTube retires the player
# clients it impersonates every few weeks, and a stale copy is refused with a
# bare 403 the moment a download starts. The app keeps its own copy current -
# vidichord/pipeline/ytdlp_update.py upgrades it at every start and once a day
# when PyPI has a newer release, and again on the spot when YouTube refuses -
# so this floor only has to be new enough to get the first song through.
#
# The "default" extra matters. Descrambling a YouTube streaming URL means
# running the player's JavaScript, and yt-dlp ships the script that does it
# only for Deno and Bun; Node - the engine most machines actually have - needs
# the yt-dlp-ejs package. yt-dlp checks that script's version and hash against
# its own vendored manifest and silently ignores a mismatch, which looks
# exactly like not having the package at all. The extra pins the exact
# yt-dlp-ejs release each yt-dlp expects, so installing the pair this way
# keeps them matched by construction; the release build asserts it anyway.
# (The extra also brings brotli, mutagen, pycryptodomex and websockets, which
# yt-dlp uses when present - all small, all with Windows wheels.)
yt-dlp[default]>=2026.8.19
requests>=2.31

# --- transcription ---
# 1.1 is the floor that knows the "large-v3-turbo" model alias.
faster-whisper>=1.1

# --- audio analysis ---
librosa>=0.10
soundfile>=0.12
numpy>=1.26
scipy>=1.11

# --- stem separation (optional) ---
# Deliberately not listed here either, for a different reason than madmom's: it
# installs perfectly well (`pip install demucs` - every dependency has a
# Windows wheel and none needs a compiler), but it brings PyTorch, about 400 MB
# installed, which is more than the rest of this application weighs. That is
# too much to impose on everyone who only wants a chord sheet, and far too much
# to put inside a single-file executable that unpacks itself on every launch.
#
# With it, every song is split into vocals, drums, bass and other: the player
# turns those into faders, and stage 2 transcribes the isolated vocal, which is
# where Whisper's word timings are at their best. Without it, songs import
# exactly as they did before - stage 5 records why it separated nothing and
# every later stage works from the full mix.
#
#   backend\.venv\Scripts\pip install demucs
#
# or run devops\scripts\run_local.bat --with-stems once.

# --- development ---
# Not needed to run the app, but needed to release it: the release build runs
# the suite as step 4 and refuses to build from a red one, so a venv without
# these fails with "No module named pytest" and blames the tests for it.
# httpx is what fastapi.testclient runs on, and FastAPI does not pull it in.
pytest>=8.0
httpx>=0.27

# --- madmom (optional) ---
# Deliberately not listed here: it cannot be installed by a plain `pip install
# -r`. The PyPI sdist ships C files generated by an old Cython that include
# longintrepr.h, a header removed in Python 3.12, and its setup.py imports
# Cython without declaring it as a build dependency. setup.bat installs it
# from git with --no-build-isolation, which works. Requires a C compiler and
# Python 3.12 or older.
#
# Without madmom the app still runs: bar lines are estimated from onset energy
# rather than tracked, and chords are fused from two engines instead of three.
